## 能否沿用服务器上原有依赖？

**可以。** 推荐复用已有 `/opt/devmind-ai/.venv`，不必删掉重装。

| 情况 | 做法 |
|------|------|
| 已是 Python 3.12，且上次 `uv sync` 已装齐 torch 等大包 | **保留 `.venv`**，解压代码后执行 `uv sync --frozen --python 3.12`（只补差异，通常很快） |
| 之前误用 3.14 导致 sync 失败 | 删除 `.venv`，再 `uv python install 3.12 && uv sync --python 3.12` |
| 仅改了业务代码、`uv.lock` 无实质变化 | `uv sync --frozen` 几乎秒过，无需重新下载模型 |

> 模型目录 `internal_kb_qa/models/` **不要**随 zip 覆盖；服务器上已下载的模型继续用。

## 3.1 第一步：打包

### 3.1.1 打包前端

```bash
cd front
npm ci
npm run build
# 产物目录：front/dist/
```

Windows PowerShell：

```powershell
cd E:\tianxuan\DevMind-AI\front
npm ci
npm run build
```

生产环境 API 地址在构建时注入（Nginx 同域反代可留空）：

```bash
# 若 API 与前端不同域，构建前创建 front/.env.production：
echo 'VITE_API_BASE_URL=' > front/.env.production
```

### 3.1.2 打包后端（zip）

> **Windows 注意**：PowerShell 默认没有 `zip` 命令，请用下方 **PowerShell 脚本** 或 **`tar`**，不要直接复制 Linux 的 `zip -r` 命令。

**方式一：一键脚本（推荐）**

Linux / macOS / WSL：

```bash
chmod +x scripts/pack-release.sh
./scripts/pack-release.sh
```

Windows（在项目根目录执行）：

```powershell
cd E:\tianxuan\DevMind-AI
powershell -ExecutionPolicy Bypass -File .\scripts\pack-release.ps1
```

仅打包后端（跳过前端构建，适合已 `npm run build` 过）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\pack-backend.ps1
```

输出目录：`dist/release/devmind-ai-frontend-*.zip`、`dist/release/devmind-ai-backend-*.zip`

**方式二：手动打包（Linux / macOS / WSL）**

```bash
cd /path/to/DevMind-AI
mkdir -p dist/release
DATE_TAG=$(date +%Y%m%d_%H%M%S)
zip -r "dist/release/devmind-ai-backend-${DATE_TAG}.zip" \
  backend base internal_kb_qa mysql_qa rag_qa \
  new_main.py app.py config.ini pyproject.toml uv.lock .python-version \
  sql docker scripts locust_test.py \
  -x "**/__pycache__/*" "**/*.pyc" "**/.venv/*" "**/node_modules/*" "**/data/uploads/*" "**/logs/*" "**/.git/*" "**/internal_kb_qa/models/*"
```

**方式三：手动打包（Windows，无需安装 zip）**

```powershell
cd E:\tianxuan\DevMind-AI
$tag = Get-Date -Format "yyyyMMdd_HHmmss"
New-Item -ItemType Directory -Force -Path dist\release | Out-Null
tar -a -cf "dist\release\devmind-ai-backend-$tag.zip" `
  --exclude=internal_kb_qa/models `
  --exclude=**/__pycache__ `
  backend base internal_kb_qa mysql_qa rag_qa `
  new_main.py app.py config.ini pyproject.toml uv.lock .python-version `
  sql docker scripts locust_test.py
```

> **为何排除 `internal_kb_qa/models/`？** 本地模型约 4GB+；服务器继续使用已有模型，无需重下。

## 3.2 第二步：上传

### 3.2.1 上传命令

在**本地开发机**执行，将 zip 传到服务器 `/opt/`：

```bash
scp dist/release/devmind-ai-frontend-*.zip root@8.211.188.59:/opt/
scp dist/release/devmind-ai-backend-*.zip root@8.211.188.59:/opt/
```

### 3.2.2 解压文件

登录服务器后操作（**全程使用绝对路径**）：

```bash
ssh root@8.211.188.59

yum install -y unzip    # 若无 unzip；Ubuntu 用 apt install -y unzip

mkdir -p /opt/devmind-ai/front/dist
ls -lh /opt/devmind-ai-frontend-*.zip /opt/devmind-ai-backend-*.zip
```

**方式 A：文件名已知时（推荐）**

将日期后缀换成你 `ls` 看到的实际文件名：

```bash
FRONT_ZIP=/opt/devmind-ai-frontend-YYYYMMDD_HHMMSS.zip
BACKEND_ZIP=/opt/devmind-ai-backend-YYYYMMDD_HHMMSS.zip

# 建议先备份当前代码（不含 .venv / models）
mkdir -p /opt/devmind-ai-backup
cp -a /opt/devmind-ai/backend /opt/devmind-ai/config.ini /opt/devmind-ai-backup/ 2>/dev/null || true

unzip -o "$FRONT_ZIP" -d /opt/devmind-ai/front/dist
unzip -o "$BACKEND_ZIP" -d /opt/devmind-ai
```

**方式 B：自动选 /opt 下最新一份 zip**

```bash
FRONT_ZIP=$(ls -t /opt/devmind-ai-frontend-*.zip 2>/dev/null | head -1)
BACKEND_ZIP=$(ls -t /opt/devmind-ai-backend-*.zip 2>/dev/null | head -1)

echo "backend:  $BACKEND_ZIP"

unzip -o "$FRONT_ZIP" -d /opt/devmind-ai/front/dist
```

## 3.3 第三步：依赖同步（复用原有 .venv）

```bash
cd /opt/devmind-ai

# 确认 Python 版本（应为 3.12.x 或 3.13.x）
uv run python --version

# 复用已有虚拟环境：只按 lock 补齐差异，不重装全部大包
uv sync --frozen --python 3.12
```

若提示没有 3.12：

```bash
uv python install 3.12
uv sync --frozen --python 3.12
```

**仅当** 曾用 3.14 建过坏环境时才重建：

```bash
rm -rf .venv
uv python install 3.12
uv sync --python 3.12
```

模型已存在则跳过下载；缺失时再执行（**国内必须先设镜像，否则约 1MB/s 极慢**）：

```bash
cd /opt/devmind-ai
export HF_ENDPOINT=https://hf-mirror.com
grep -q 'HF_ENDPOINT' ~/.bashrc || echo 'export HF_ENDPOINT=https://hf-mirror.com' >> ~/.bashrc

# 若上次中断导致缺 model.safetensors，先删半截目录
# rm -rf internal_kb_qa/models/bge-reranker-v2-m3

uv run python -m internal_kb_qa.scripts.download_models bge-m3
uv run python -m internal_kb_qa.scripts.download_models bge-reranker-v2-m3
```

镜像仍慢时：

- ModelScope 直下，或  
- **可选项：本机下载后上传解压**（含上传带宽自测）  

详见 **[DEPLOYMENT.md §3.4.3～§3.4.4](../../DEPLOYMENT.md)**。

## 3.4 第四步：环境变量（增量必查）

编辑 `/opt/devmind-ai/backend/.env`（systemd / Docker 均读此文件）：

```ini
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=<你的密码>
MYSQL_DATABASE=internal_tech_kb

REDIS_HOST=127.0.0.1
REDIS_PORT=16379

JWT_SECRET=<至少32位随机字符串>
SSO_MODE=jwt
APP_DEBUG=false

# OSS（启用时必填）
OSS_ENABLED=true
OSS_ACCESS_KEY_ID=<RAM AccessKey ID>
OSS_ACCESS_KEY_SECRET=<RAM AccessKey Secret>

# DashScope（问答 / Query 改写 / 意图分类）
DASHSCOPE_API_KEY=<百炼 API Key>
```

> `SSO_MODE=jwt` 且 `JWT_SECRET` 已配置时，工作台登录 token 可直连 `/api/query`、`WS /api/stream`。  
> 勿把密钥写进 `config.ini` 或提交仓库。

## 3.5 第五步：重启服务

**宿主机 systemd（推荐）：**

```bash
sudo cp /opt/devmind-ai/docker/systemd/devmind-backend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl restart devmind-backend
sudo systemctl status devmind-backend

# Nginx 若前端有更新
sudo nginx -t && sudo systemctl reload nginx
```

**前台验证（可选）：**

```bash
cd /opt/devmind-ai
uv run uvicorn backend.app.main:app --host 127.0.0.1 --port 8004
```

日志中应出现类似：`问答系统已挂载到后端（sso_mode=jwt, ...）`。

## 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `spacy` / `cp314` 安装失败 | 用了 Python 3.14 | 换 3.12，删坏 `.venv` 后 `uv sync` |
| `ModuleNotFoundError: new_main` / `mysql_qa` | 旧 zip 未打入问答包 | 使用本次补全后的后端 zip 重新解压 |
| `/api/query` 401 | 正常（需登录 JWT） | 确认 `SSO_MODE=jwt` 且 `JWT_SECRET` 与签发一致 |
| `/api/query` 404 | 仍在跑旧进程或旧代码 | `systemctl restart`，确认 `main.py` 含 `qa_api_router` |
| `uv sync` 很慢 | 首次装 torch/CUDA | 保留 `.venv`，下次会快；勿反复 `rm -rf .venv` |
