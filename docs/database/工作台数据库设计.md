# DevMind AI 工作台数据库设计

推荐 PostgreSQL 16。向量索引由 Milvus 保存；PostgreSQL 保存业务事实、权限、会话、消息、引用映射和审计日志。所有主键使用 UUID，时间统一 `timestamptz`。

## 数据关系

```text
organizations 1─* users 1─* chat_sessions 1─* chat_messages 1─* message_citations *─1 document_chunks *─1 documents *─1 knowledge_bases
users 1─* auth_identities
users 1─* auth_refresh_tokens
users *─* knowledge_bases (knowledge_base_members)
users *─* chat_messages (message_favorites)
```

## 核心表

| 表 | 主要字段 | 说明与索引 |
| --- | --- | --- |
| `organizations` | `id`, `name`, `sso_provider`, `created_at` | 租户边界；`name` 唯一 |
| `users` | `id`, `organization_id`, `external_subject`, `email`, `phone_e164`, `display_name`, `avatar_url`, `status`, `email_verified_at`, `phone_verified_at` | 唯一 `(organization_id, email)`、`phone_e164` 非空时唯一；账号主体与显示资料 |
| `auth_identities` | `id`, `user_id`, `provider`, `provider_subject`, `password_hash`, `password_updated_at`, `created_at` | 唯一 `(provider, provider_subject)`；本地账号 `provider=local_password`，只保存 Argon2id/bcrypt 哈希，不保存明文密码 |
| `auth_refresh_tokens` | `id`, `user_id`, `token_hash`, `device_name`, `ip_hash`, `expires_at`, `revoked_at`, `created_at` | 每个登录设备一条；只存刷新令牌哈希，索引 `(user_id, revoked_at)` |
| `phone_verification_challenges` | `id`, `phone_e164`, `purpose`, `code_hash`, `expires_at`, `consumed_at`, `attempt_count`, `created_at` | 可改由 Redis TTL 实现；仅保存验证码哈希，`purpose`: `login/register/reset_password` |
| `knowledge_bases` | `id`, `organization_id`, `name`, `description`, `status`, `document_count`, `created_by` | 索引 `(organization_id, status)` |
| `knowledge_base_members` | `knowledge_base_id`, `user_id`, `role` | 联合主键；`role`: `viewer/editor/admin` |
| `documents` | `id`, `knowledge_base_id`, `name`, `source_type`, `storage_key`, `mime_type`, `size_bytes`, `status`, `checksum`, `metadata`, `created_by` | 索引 `(knowledge_base_id, status, created_at desc)`；`checksum` 用于去重 |
| `document_chunks` | `id`, `document_id`, `chunk_no`, `content`, `content_hash`, `location_label`, `token_count`, `milvus_pk`, `metadata` | 唯一 `(document_id, chunk_no)`；Milvus `pk` 回查映射 |
| `chat_sessions` | `id`, `organization_id`, `user_id`, `title`, `knowledge_base_ids`, `last_message_at`, `created_at` | 索引 `(user_id, last_message_at desc)` |
| `chat_messages` | `id`, `session_id`, `parent_message_id`, `role`, `content`, `mode`, `status`, `confidence`, `citation_count`, `model`, `usage`, `error_code`, `created_at`, `completed_at` | 索引 `(session_id, created_at)`；`role`: `user/assistant/system` |
| `message_citations` | `id`, `message_id`, `chunk_id`, `rank`, `score`, `excerpt`, `claim` | 唯一 `(message_id, rank)`；索引 `message_id` |
| `message_favorites` | `user_id`, `message_id`, `created_at` | 联合主键；保证一人一条收藏 |
| `message_feedback` | `id`, `message_id`, `user_id`, `rating`, `reason`, `comment`, `ticket_id`, `created_at` | `rating`: `up/down/handoff` |
| `user_preferences` | `user_id`, `default_knowledge_base_ids`, `default_mode`, `locale`, `updated_at` | 一对一，`user_id` 主键 |
| `retrieval_runs` | `id`, `message_id`, `query`, `rewritten_query`, `top_k`, `rerank_top_n`, `retrieved_count`, `reranked_count`, `latency_ms`, `created_at` | 测试页和回答链路共用；索引 `(message_id)` |
| `retrieval_results` | `id`, `retrieval_run_id`, `chunk_id`, `stage`, `rank`, `score` | 唯一 `(retrieval_run_id, stage, rank)` |
| `audit_logs` | `id`, `organization_id`, `user_id`, `action`, `resource_type`, `resource_id`, `request_id`, `ip_hash`, `metadata`, `created_at` | 索引 `(organization_id, created_at desc)`；只存查询摘要，不存密文/原始令牌 |

## 建表关键片段

```sql
create table chat_messages (
  id uuid primary key,
  session_id uuid not null references chat_sessions(id) on delete cascade,
  parent_message_id uuid references chat_messages(id),
  role varchar(16) not null check (role in ('user','assistant','system')),
  content text not null default '',
  mode varchar(24) not null default 'tech',
  status varchar(16) not null default 'pending',
  confidence varchar(8) check (confidence in ('low','medium','high')),
  citation_count integer not null default 0,
  model varchar(128), usage jsonb not null default '{}',
  error_code varchar(64), created_at timestamptz not null default now(), completed_at timestamptz
);
create index idx_chat_messages_session_created on chat_messages(session_id, created_at);

create table auth_identities (
  id uuid primary key,
  user_id uuid not null references users(id) on delete cascade,
  provider varchar(32) not null,
  provider_subject varchar(255) not null,
  password_hash text,
  password_updated_at timestamptz,
  created_at timestamptz not null default now(),
  unique(provider, provider_subject),
  check ((provider = 'local_password' and password_hash is not null) or provider <> 'local_password')
);

create table message_citations (
  id uuid primary key,
  message_id uuid not null references chat_messages(id) on delete cascade,
  chunk_id uuid not null references document_chunks(id),
  rank smallint not null, score numeric(5,4) not null check (score between 0 and 1),
  excerpt text not null, claim text, unique(message_id, rank)
);
```

## 数据一致性与安全

1. 所有业务查询必须先以 `organization_id` 和资源成员关系过滤；不以传入 UUID 判断权限。
2. 文档删除采用软删除（`deleted_at`），由异步任务清理对象存储与 Milvus 向量。
3. 流式回答：创建 `user` 与 `assistant/pending` 消息后再连接 WebSocket，`final` 事务中更新回答、引用、检索运行和会话时间。
4. `document_chunks.content` 应使用数据库加密或受控磁盘；日志中只保存长度受限的查询摘要。
5. 登录挑战码必须限频、一次性消费且设短 TTL（建议 5 分钟）；生产环境优先放 Redis，不在审计日志、事件流或前端状态中记录验证码。
6. Access Token 使用短有效期；刷新令牌仅以哈希持久化，退出登录时撤销当前令牌并清除浏览器 Cookie。
