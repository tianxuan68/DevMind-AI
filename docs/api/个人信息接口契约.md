# DevMind AI 个人信息接口契约

本文件定义个人信息编辑页的读取与保存接口。仅作为后端实现契约，不修改现有后端代码。

基础地址：`http://localhost:8003/api/v1`。所有请求使用 Access Token 获取当前用户，不允许客户端传入或修改 `user_id`。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/me/profile` | 读取个人档案与使用偏好 |
| PATCH | `/me/profile` | 保存个人档案与使用偏好 |

统一响应：

```json
{ "request_id": "req_xxx", "data": {}, "error": null }
```

## 读取个人信息

`GET /me/profile`

```json
{
  "request_id": "req_profile_01",
  "data": {
    "display_name": "张工程师",
    "avatar_url": null,
    "gender": "male",
    "birth_date": "1998-08-12",
    "email": "zhang@example.com",
    "phone": "+8613800138000",
    "department_name": "平台研发部",
    "job_title": "高级后端工程师",
    "employee_no": "DM-2024-018",
    "joined_at": "2024-03-18",
    "bio": "专注企业平台与知识系统研发。",
    "timezone": "Asia/Shanghai",
    "locale": "zh-CN",
    "updated_at": "2026-08-23T10:00:00Z"
  },
  "error": null
}
```

## 保存个人信息

`PATCH /me/profile`

```json
{
  "display_name": "张工程师",
  "avatar_url": null,
  "gender": "male",
  "birth_date": "1998-08-12",
  "email": "zhang@example.com",
  "phone": "+8613800138000",
  "department_name": "平台研发部",
  "job_title": "高级后端工程师",
  "employee_no": "DM-2024-018",
  "joined_at": "2024-03-18",
  "bio": "专注企业平台与知识系统研发。",
  "timezone": "Asia/Shanghai",
  "locale": "zh-CN"
}
```

成功时返回保存后的完整对象。前端以响应内容更新侧栏中的头像、姓名、职位与部门。

## 字段规则

| 字段 | 规则 |
| --- | --- |
| `display_name` | 1–64 个字符，必填 |
| `gender` | `male`、`female`、`unspecified` |
| `birth_date` | ISO 日期；不得晚于今天 |
| `email` | 合法邮箱；同组织唯一；变更后建议进入邮箱验证流程 |
| `phone` | E.164 格式；变更后必须通过短信验证码验证 |
| `department_name` | 1–128 个字符 |
| `job_title` | 1–128 个字符 |
| `employee_no` | 最多 64 个字符；同组织非空时唯一 |
| `joined_at` | ISO 日期；不得晚于今天 |
| `bio` | 最多 500 个字符 |
| `timezone` | 合法 IANA 时区 |
| `locale` | 如 `zh-CN`、`en-US` |

返回错误码：`PROFILE_VALIDATION_FAILED`、`EMAIL_ALREADY_EXISTS`、`PHONE_ALREADY_EXISTS`、`EMPLOYEE_NO_ALREADY_EXISTS`、`PHONE_VERIFICATION_REQUIRED`。

## 后端持久化要求

1. 基础档案写入 `user_profiles`，邮箱和手机号等账号字段写入 `users`；时区、语言在同一事务中写入 `user_preferences`。
2. 邮箱或手机号修改不得直接生效：先创建验证挑战，验证通过后才更新 `users`。
3. 写入成功后记录 `audit_logs`，动作名为 `user.profile.updated`，不要记录生日、手机号和简介原文。
4. 如后续接入 SSO，可由服务端返回 `editable_fields`；前端将未授权字段展示为只读，而不依赖硬编码。

## 当前前端行为

当前前端使用本地 Mock 状态展示保存成功与侧栏同步。后端实现本接口后，前端保存按钮应改为调用 `PATCH /me/profile`，并仅在成功响应后更新本地状态。
