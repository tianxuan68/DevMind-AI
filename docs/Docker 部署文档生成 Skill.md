# Docker Deployment Documentation Skill

## 1. Skill 名称

`docker-deployment-doc-generator`

---

## 2. Skill 目标

根据项目提供的 Docker、Docker Compose、环境变量、配置文件、服务依赖及部署脚本，自动生成一份：

- 简单明了
- 面向运维人员
- 可直接执行
- 结构统一
- 以 Docker 部署为核心
- Markdown 格式

的项目部署文档。

文档重点是**部署、启动、停止、重启、查看日志、更新、回滚、备份、故障排查**，避免加入与运维无关的大量技术说明。

---

## 3. 输入

Skill 可以接收以下任意一种或多种内容：

```text
docker-compose.yml
Dockerfile
.env
.env.example
README.md
部署脚本
配置文件
项目目录结构
服务端口信息
数据库配置
Redis 配置
向量数据库配置
Nginx 配置
项目说明
```

---

## 4. 输出

输出文件：

```text
DEPLOYMENT.md
```

输出格式：

```text
Markdown
```

---

## 5. 核心原则

### 5.1 不编造

只能使用输入中能够确认的信息。

禁止：

```text
自行创建端口
自行创建账号密码
自行创建服务名称
自行猜测数据库
自行猜测启动命令
自行猜测目录
自行猜测环境变量
```

无法确认时统一使用：

```text
待确认
```

---

### 5.2 优先真实配置

信息优先级：

```text
实际 Docker Compose 配置
        ↓
Dockerfile
        ↓
环境变量配置
        ↓
部署脚本
        ↓
项目 README
        ↓
用户提供的文字说明
```

如果不同来源存在冲突：

```text
以实际部署配置为准
```

---

### 5.3 面向运维

文档主要回答：

```text
怎么部署？
怎么启动？
怎么停止？
怎么重启？
怎么看状态？
怎么看日志？
怎么更新？
怎么回滚？
怎么备份？
怎么恢复？
服务异常怎么办？
端口冲突怎么办？
容器启动失败怎么办？
```

避免输出：

```text
代码实现原理
业务代码介绍
算法原理
详细开发教程
```

---

## 6. 信息分析流程

生成文档前必须先分析项目。

### Step 1：识别项目类型

判断：

```text
Docker
Docker Compose
单容器
多容器
前后端分离
微服务
数据库服务
缓存服务
向量数据库
消息队列
反向代理
```

---

### Step 2：识别服务

提取：

```text
服务名称
镜像
容器名称
端口
环境变量
数据卷
网络
依赖关系
启动命令
健康检查
```

---

### Step 3：识别持久化数据

分析：

```text
volume
bind mount
数据库目录
日志目录
配置目录
上传文件目录
模型目录
```

标记哪些数据：

```text
必须备份
建议备份
无需备份
```

---

### Step 4：识别部署命令

从配置中提取实际命令。

例如：

```bash
docker compose up -d
docker compose down
docker compose restart
docker compose ps
docker compose logs
docker compose pull
```

禁止自行修改为其他命令。

---

### Step 5：识别服务依赖

生成：

```text
应用
 ↓
数据库
 ↓
Redis
 ↓
向量数据库
```

或者根据实际项目生成对应关系。

---

## 8. 内容生成规则

### 8.1 项目概述

只说明：

```text
项目用途
部署方式
核心服务
```

控制在：

```text
1~3 段
```

---

### 8.2 环境要求

自动提取：

```text
操作系统
Docker 版本
Docker Compose 版本
CPU
内存
磁盘
```

如果项目无法确认硬件要求：

```text
不编造
```

---

### 8.3 服务说明

使用表格：

```text
| 服务 | 镜像 | 端口 | 用途 | 数据持久化 |
|---|---|---|---|---|
```

---

### 8.4 配置说明

自动识别 `.env` 和 Compose 中的环境变量。

使用：

```text
| 配置项 | 说明 | 是否必填 | 示例 |
|---|---|---|---|
```

敏感信息禁止直接输出真实值：

```text
密码
API Key
Token
Secret
Access Key
Private Key
```

使用：

```text
<请填写>
```

---

### 8.5 部署步骤

必须保证运维人员可以按照顺序直接执行。

统一结构：

```text
1. 获取项目
2. 配置环境变量
3. 检查配置
4. 拉取镜像
5. 启动服务
6. 查看服务状态
7. 查看日志
8. 健康检查
```

每一步优先提供：

```bash
实际可执行命令
```

---

### 8.6 常用运维命令

必须至少包含：

```text
启动
停止
重启
查看状态
查看日志
进入容器
查看资源
查看镜像
```

命令必须以项目实际使用的 Docker / Docker Compose 版本为依据。

---

### 8.7 服务验证

必须提供：

```text
容器状态检查
端口检查
健康检查
API 检查
核心依赖检查
```

示例结构：

```bash
# 检查容器
<command>

# 检查端口
<command>

# 健康检查
<command>
```

---

### 8.8 更新部署

按照：

```text
备份
 ↓
拉取新镜像
 ↓
停止旧服务
 ↓
启动新服务
 ↓
检查状态
 ↓
验证服务
```

生成实际命令。

---

### 8.9 数据备份

自动识别持久化数据。

分别生成：

```text
数据库备份
文件备份
Volume 备份
配置备份
```

无法确定备份方案时：

```text
明确标记待确认
```

禁止虚构备份命令。

---

### 8.10 日志管理

至少包含：

```text
查看全部日志
查看指定服务日志
实时日志
最近 N 行日志
日志目录
日志清理
```

---

### 8.11 故障排查

必须优先覆盖：

```text
容器无法启动
容器反复重启
端口被占用
数据库连接失败
Redis 连接失败
服务无法访问
镜像拉取失败
磁盘空间不足
权限问题
```

每个问题统一格式：

```text
### 问题名称

#### 现象

#### 排查命令

#### 可能原因

#### 处理方式

#### 验证方式
```

---

### 8.12 回滚

如果项目存在版本控制或镜像 Tag：

```text
优先生成实际回滚流程
```

如果无法确认：

```text
回滚方式：待确认
```

禁止虚构版本号。

---

## 9. 命令生成规则

命令必须：

```text
可复制
可执行
与项目配置一致
```

命令前说明用途。

例如：

```bash
# 查看所有服务状态
docker compose ps
```

禁止出现：

```text
# 执行下面命令即可
```

但没有实际命令。

---

## 10. 敏感信息处理

检测以下字段：

```text
PASSWORD
TOKEN
SECRET
API_KEY
ACCESS_KEY
PRIVATE_KEY
```

输出时：

```text
实际值 → <请填写>
```

禁止把用户真实密钥写入最终文档。

---

## 11. Markdown 格式规则

统一使用：

```text
# 一级标题

## 二级标题

### 三级标题
```

命令必须使用：

```markdown
```bash
...
```
```

配置必须使用表格：

```markdown
| 配置项 | 说明 |
|---|---|
```

状态检查可以使用：

```markdown
- [ ] Docker 正常
- [ ] 容器正常
- [ ] 服务正常
- [ ] 数据库正常
```

---

## 12. 简洁性规则

文档以：

```text
能让新运维人员快速部署
```

为目标。

避免：

```text
长篇背景介绍
源码分析
框架原理
复杂架构解释
无关技术说明
重复命令
```

每个章节优先：

```text
说明 + 命令 + 验证
```

---

[ ] 镜像一致
[ ] 环境变量一致

```

### 命令一致性

```text

[ ] 停止命令可用
[ ] 重启命令可用
[ ] 日志命令可用
[ ] 状态命令可用
```

### 运维完整性

```text
[ ] 部署
[ ] 启动
[ ] 停止
[ ] 重启
[ ] 日志
[ ] 更新
[ ] 备份
[ ] 恢复
[ ] 回滚
[ ] 故障排查
```

### 安全性

```text
[ ] 无明文密码
[ ] 无 API Key
[ ] 无 Token
[ ] 无 Private Key
```

---

## 14. 最终输出要求

最终只输出：

```text
DEPLOYMENT.md
```

不要额外输出：

```text
分析过程
推理过程
项目源码解释
无关建议
```

最终文档必须让运维人员可以按照：

```text
环境准备
→ 配置
→ 启动
→ 验证
→ 日常运维
→ 更新
→ 故障排查
→ 回滚
```

完成整个 Docker 部署生命周期。
